## What was built
- `dispatch.max_parallel` (default 1). At 1 the pass is the pre-SEL-004 pass, byte for byte against a transcript recorded from main 77464f1.
- Above 1: the planner launches non-exclusive tasks whose `Touches` is disjoint from every running or earlier-waiting task. Each runs in `.worktrees/<stem>` on `task/<stem>` under a detached supervisor (`seldon dispatch supervise`) holding `.seldon/leases/<stem>.lock`. Exclusive tasks run in place, alone, under the pass lease, as before; a waiting exclusive task blocks new launches (writer preference).
- Merge on green: clean worktree, rebase onto main, re-gate (`dispatch.gate_command`) when main changed a file in the write set (union files excepted), union-file check, spec-hash check, then under the pass lease fast-forward only if main has not moved (bounded retries). Then the dispatcher completes the task, pushes and removes the worktree. Any failure is `merge_blocked`: the task is blocked, `dispatch_merge: merge_blocked` is set, an Issue (`issue_type: merge_blocked`, `remediated_by` the task) names the files, the operator is notified, and the worktree is kept.
- Shared append-only files: `primary_checkout()` / `$SELDON_PRIMARY_CHECKOUT` plus `locked()` (the flock discipline of `kg/spend.py`). `dispatch.shared_paths` files are committed by the pass and are not c7 dirt.
- Recovery: a dead supervisor PID leads the next pass to block the task (`outcome: holder_gone`). The worktree and lease are kept; `lease reap --task <stem>` releases the lease and is PID-gated. `status` and `go` show worktree leases.

## Header grammar as implemented
`**Exclusive:** yes|no` (absent = yes). `**Touches:** none` or comma-separated items. Each item is a bare word that must be a key of `dispatch.resources`, or a repo-relative fnmatch glob (trailing `/` = directory, `./name` for a dotless root file, no absolute paths, no `..`, no whitespace). `Exclusive: no` requires Touches. A parse failure is c10 `concurrency_undeclared` with the grammar quoted, in serial mode too. A task with neither header gets no c10.
